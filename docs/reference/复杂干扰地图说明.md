# Map06–Map08：复杂地形与特殊区域测试集

生成日期：2026-09-20。三张地图是新增的本地训练/压力测试地图，使用本仓库的 `MapAbstract`、`ClosedPlayground`、碰撞系统、红蓝双方接口和 YAML 评测格式；不是主办方发布的正式隐藏地图。

## 1. 地图概览

| 地图 | 名称 | 尺寸（像素） | 地形 | 重点考察 |
|---|---|---|---|---|
| Map06 | 通信断层城 | 1680 × 1260 | 12 个连通房间、错位门洞、L 形内墙、箱体 | 断联后的独立决策、恢复通信后的任务合并 |
| Map07 | 失导航仓储区 | 1800 × 1440 | 多排长货架、错位通道、多路径连接 | 无 GPS/指南针条件下的里程计导航、携弹过道 |
| Map08 | 斜墙复合迷宫 | 1600 × 1600 | 16 个房间、斜墙、L 形遮挡、多个转角 | 不完整建图、斜墙避障、危险区绕行 |

每张地图各有 2 个禁通信区、2 个无 GPS 区、2 个杀戮区，共 6 个特殊区。蓝方默认预置 10 枚静止炸弹。红方启动时由标准 launcher 清除预置炸弹，再给 5 架无人机各分配 2 枚库存。蓝方默认 10 架无人机。

三张地图采用区别于 Map01–Map05 的尺寸；没有把新墙图或新炸弹位置写入参赛算法的公开地图先验。布局数据只由模拟器读取。

## 2. 特殊区域的真实效果

| 区域 | 颜色 | 仿真效果 | 离开后 |
|---|---|---|---|
| NO_COM_ZONE | 透明黄色 | 区域内无人机的 Communicator 禁用，不能发送或接收无线消息 | 恢复通信，可重新同步账本 |
| NO_GPS_ZONE | 透明灰色 | GPS 和 Compass 禁用，读取值为 None；Lidar 和 Odometer 保留 | GPS 和指南针恢复 |
| KILL_ZONE | 透明粉色 | 无人机机体接触即生命值归零，同一物理步结束时释放抓持物并移除无人机 | 不复活 |

禁通信沿用仓库的“区域内设备禁用”语义，不额外模拟区外两架无人机之间无线信号穿过该区域的传播遮挡。通信与定位区使用原有 `NoComZone` 和 `NoGpsZone`，透明度使用引擎 `SPECIAL_ZONE_ALPHA`。

原仓库 `KillZone` 只有设备停用和外观变更效果。为满足本次“瞬间摧毁”的要求，新地图使用 `LethalKillZone`，额外监听机体接触，将生命值置零，并在物理引擎安全的 post-step 回调中移除。未改变旧地图的 `KillZone` 行为。粉色区附近设备可能先进入区域而失效；机体接触时才触发永久摧毁。

这些区域不是实体墙，不应写进红方提交的墙图。出生位置也不是返航区；本测试集没有增设返航区，健康分继续使用仓库无返航区时的全场统计规则。

## 3. 可达性设计

- 主要门洞为 160–180 像素，门洞位置交错，不能靠直线巡航穿过所有房间。
- 障碍物、处置中心和杀戮区均作为不可通行区，向外保留 40 像素圆形安全半径后，所有 10 个测试目标仍与出生中心连通。
- 每张图的处置中心右侧有可达接近点，出生编队与墙、处置中心及特殊区保持间隔。
- 杀戮区没有封死唯一必经路线，预置炸弹不在杀戮区内。
- 部分目标在无 GPS 或禁通信区内，需要算法处理真实的传感器缺失。

40 像素检查是保守的几何连通性验证，不代表当前红蓝算法已能完成这些地图，也不保证每一种抓持姿态都能无碰撞通过。

## 4. 启动与配置

最简单的方法：在 `output/challenge_maps/` 中双击 `run_place_Map06.cmd`（红方）或 `run_rescue_Map06.cmd`（蓝方）；Map07、Map08 同理。

命令行在仓库根目录执行：

```powershell
# 红方 Map06，显示仿真窗口
.\.venv\Scripts\python.exe -m swarm_rescue.launcher --competition --config config/challenge_place_Map06.yml

# 蓝方 Map08，无窗口运行并记录回放
.\.venv\Scripts\python.exe -m swarm_rescue.launcher --headless --competition --config config/challenge_rescue_Map08.yml
```

六份配置默认开启全部区域：

```yaml
zones_config: [NO_COM_ZONE, NO_GPS_ZONE, KILL_ZONE]
```

将其改成 `[]` 可只测试地形，或保留部分区域进行消融。Python 直接创建地图时仍遵循仓库约定，省略 `zones_config` 表示不启用特殊区。

回合上限：9600 仿真步、360 秒墙钟时间。配置启用 NPZ 状态记录，回放文件位于 `results_swarm_rescue/<本轮目录>/recordings/`。本次补充了回放中的 `zones_config` 元数据，重播会恢复同样的特殊区域；旧回放没有这个字段时沿用旧行为。

```powershell
.\.venv\Scripts\python.exe -m swarm_rescue.launcher --replay "<实际回放路径.npz>"
```

## 5. 文件与修改方式

| 文件 | 用途 |
|---|---|
| `src/swarm_rescue/maps/map_06.py` 至 `map_08.py` | 标准地图入口类 |
| `src/swarm_rescue/maps/challenge_map.py` | 地图初始化、特殊区、出生编队与永久摧毁逻辑 |
| `src/swarm_rescue/maps/challenge_layouts.py` | 模拟器专用布局数据 |
| `map_data/map_06.json` 至 `map_08.json` | 原编辑器格式的墙、起点、处置中心数据 |
| `map_data/map_06.png` 至 `map_08.png` | 带目标和区域标记的设计预览 |
| `map_data/bombs_Map06_challenge.json` 等 | 标准炸弹文件格式的 10 目标测试布局 |
| `config/challenge_place_Map06.yml` 等 | 6 份红蓝比赛模式启动配置 |
| `output/challenge_maps/Map06_simulator.png` 等 | 实际模拟器渲染图 |
| `scripts/build_challenge_maps.py` | 地形定义与可复现生成器 |
| `scripts/validate_challenge_maps.py` | 仿真截图和 120 步集成检查 |
| `tests/test_challenge_maps.py` | 几何可达性、区域开关、传感器恢复、永久摧毁测试 |

坐标转换：设计数据使用左上角为原点的像素坐标；运行时转换为地图中心原点、Y 轴向上的世界坐标。炸弹导出 JSON 已使用世界坐标。

原地图编辑器尚不支持绘制特殊区域，所以 JSON 的 `special_zones` 是单独扩展字段；旧编辑器另存可能丢失该字段。应修改生成器中的布局定义再重新生成，不要单独编辑 JSON 后期待运行时同步变化。该扩展不冒充官方地图 JSON 的标准字段；实际评测入口是 Python 地图类和 YAML 配置。

```powershell
.\.venv\Scripts\python.exe scripts/build_challenge_maps.py
.\.venv\Scripts\python.exe -m pytest tests/test_challenge_maps.py -q -p no:cacheprovider -W ignore
.\.venv\Scripts\python.exe scripts/validate_challenge_maps.py
```

## 6. 验证范围

10 项地图自动化测试验证三图目标连通、出生安全、区域开关、禁通信、GPS/指南针失效、里程表可用、离区恢复、杀戮区永久摧毁和死亡后的回放编号稳定性。另通过标准 launcher 对每图红蓝双方各执行 120 步 competition 模式启动检查，检查配置加载、控制器执行、评分输出和带区域信息的回放保存。

同步修复引擎移除对象后未刷新存活缓存的问题；状态记录改为保留已移除对象的固定槽位，避免无人机死亡或炸弹处置后其余对象的回放编号错位。

120 步检查仅验证集成，不是完整成绩测试；它产生的分数不能用于评价算法水平。完整比赛时长和新图高分能力需要后续单独评测。
