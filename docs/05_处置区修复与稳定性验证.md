# 处置区修复、任务调度与稳定性验证

本文说明正式蓝方 v13.2（2026-10-15），源码与冻结候选 candidate25 一致。详细实测见 [验收结果](06_稳定性验收结果.md)；全部数据按记录保留，不代表任意未知地图保证成功。

## 先看验收目标

每局必须在原有比赛时限内真实归位全部炸弹，并且没有无人机被摧毁。找到、认领、抓住或带到处置区附近都不等于归位。以引擎统计的 `Rescued Percent=100`、`Crashed=0` 和正常退出为依据。

在全归位的前提下，比较完成步数、健康与总分；另外检查处置区附近的连续滞留和损血。算法只使用公开传感器、无线电消息、队伍规模与赛场尺寸/时限，不读取地图文件、炸弹真值或测试 seed。

## 为什么原来会徘徊

处置区对无人机是实体障碍。旧在线地图把“不是墙”的语义回波作为动态对象处理，规划图未稳定保留处置区。于是 A* 可能给出穿过处置区的路线，或者巡逻点落在处置区内；局部 LiDAR 避障又阻止无人机进入，两个层次给出了互相冲突的指令。

接触处置区本身并非直接扣血来源，主要损失来自反复避障时碰墙、撞机。返航失败还可能发生在普通墙端：机身能经过的路线，不一定能让挂载炸弹顺利转弯。

另外，旧引擎碰撞扣血的冷却由实际运行时间计量，相同 seed 不保证健康分完全一致。原任务报价在健康 45 附近有突然增加的成本，这会把少量健康波动放大为分工变化。实验中，旧版同代码、同布局、同 seed 也出现过一次全归位、一次未全归位，因此不能凭单次对比认定修复导致降分。

## 1. 处置区的独立障碍层

实现：`src/swarm_rescue/solutions/upgrade/disposal_navigation.py` 和 `controller_v13.py` 的 `_update_online_obstacles()`、`_plan_navigation()`、`_control_patrol()`。

无人机把语义传感器看到的处置区表面回波，结合自己的 GPS/航向估计换算为世界坐标。只在定位可信时加入本地观测；无线电转发有限数量的已观测表面点。

表面点按 8 像素网格合并，通过连通分组、凸包形成已观测范围内的障碍近似。没有观测时不生成已知处置区形状，不读取官方中心坐标或宽高。它与墙体证据图分开保存，避免非墙回波清除已经识别的处置区边界。

正常运动保持原流程。空载机持续约 88 步、移动范围不足 42 像素，并且路线穿过已观测处置区或目标落在该区域附近时，才开启这层绕行。短时限任务还保留前期搜索节奏，达到真实处置进度后才介入该分支。

若巡逻点不可进入，将该巡逻点投影到可达边缘，保留这段巡逻与扫描任务。载弹机不使用这个空载禁入层，最终处置仍要允许炸弹接触处置区。

## 2. 载弹机卡住后的净空重规划

实现：`controller_v13.py` 的载弹运动窗口和 `_plan_with_disposal_layer()`；原双圆轨迹控制仍在 `trajectory_control.py`。

全程把返航路线扩大到较大净空，会改变正常运送与前期搜索节奏，因此该方案没有采用。现在仅在载弹机持续净位移不足、目标仍在远处、未进入可见处置区的末端处置过程时，触发一次较大净空重规划。

规划优先尝试 32 像素净空，依次使用 16、8 像素规划网格。如果较大净空找不到路，仍保留原有较小净空路径，避免把长条载荷实际可以通过的窄门判成不可通行。释放载荷后清除本次返航的恢复状态。

原抓取、起载退出、54 动作/6 步预测的机身与载荷双圆检查、末端推进与释放流程保持原有实现。该方法是在线恢复启发式，不是对所有未知障碍形状的形式化碰撞保证。

## 3. 减少健康噪声引起的竞价跳变

实现：`controller_v13.py` 的 `_target_bid()`。

当无人机真实健康不少于 25/50 时，在任务报价的内部风险项中把它们视为具有相同的可用健康等级，优先依据路径与运输成本分配任务。实际健康低于 25 时，仍使用原有低健康风险模型。

这只改变任务报价，不伪造健康。无线电广播、健康显示、评分、低健康退休与速度限制仍使用引擎真实值，碰撞扣血规则不变。

作用是避免“某架无人机因为运行速度差异多扣 1 点血，任务成本突然增加，远端炸弹换人负责”的连锁变化。稳定性仍需通过重复运行检查，不能只看平均分。

## 4. 为短时限任务保留开局侦察

实现：`controller_v13.py` 的 `_opening_scout_active()`、`_own_offer()`、`_can_claim_target()`、`_control_explore()`。

队伍不少于 6 架、任务时限不超过 2000 步时，保留已有巡逻策略中最后两架探测角色，其他无人机正常搜索和搬运。侦察机照常感知、发布炸弹线索，但在开局阶段不为自己不会立即执行的搬运任务报价。

早期试验在两架侦察机的共同途经点就结束侦察，导致它们同时折返，另一侧远端区域仍无人探测。当前版本为每架记录其原巡逻路线中的独立探测目标，满足下列任一条件后才转为普通搜索/运输：

- 到达探测目标附近，或完成原有三段开局路线；
- 已接近自己的探测区域，并通过语义传感器看到近处未被抓取的炸弹；
- 达到任务时限的 45%，按超时回退释放角色。

角色释放后不会在返航途中重新进入侦察阶段。探测点来自现有基于公开赛场尺寸的巡逻路线，墙体避让仍依据在线感知，没有导入某张地图的墙体或炸弹坐标。

## 怎么重跑与核对

在项目根目录打开 PowerShell：

```powershell
.\run.ps1 Test
.\run.ps1 Run -Map Map01 -Layout historic -Seed 12345 -Headless
.\run.ps1 Run -Map Map01 -Layout edge_pairs -Seed 42 -Headless
.\run.ps1 Run -Map Map01 -Layout stratified -Seed 12347 -Headless
```

每次运行会打印结果目录，其中保存输入炸弹 JSON、配置、控制器来源、源码和布局哈希、运行日志、原始统计与 NPZ 回放。查看指定回放与复算一批成绩：

```powershell
.\run.ps1 Replay -File "结果目录\recordings\team006_Map01_none_rd1.npz"
.\run.ps1 Scores -File "结果目录或某一版本评测目录"
```

回放按空格暂停/继续，方向键调整播放速度。具体快捷键以回放窗口显示为准。评分复算使用原引擎权重：实际归位 60%、健康 20%、时间 20%，并与原始 `Round Score` 核对。

测试必须串行执行，旧新对照使用相同布局和 seed，记录源码/输入哈希；相同 seed 至少重复关键布局，再补多个 seed。不要把不同版本、不同批次的 CSV 混在一起当作一次评测成绩。

## 验证范围与发布

完整记录应包括五图三布局的旧新对照、Map1 多 seed、此前薄弱 seed、紧邻压力布局、用户提供的五局回放，以及实际归位率、健康、完成步数和分数。最终汇总表会明确已完成与未完成的项目。

任何未全归位的候选都不应只凭其他地图高分替换正式版。真实完成统计通过、分数与处置区行为复核结束后，才同步正式代码、说明和对应回放；旧结果作为历史证据保留。


## 标准回归与紧邻压力布局重跑

每条命令串行完成后再执行下一条。`-Suite`是五图各三布局，共15局；压力布局单独运行，不能混入标准五图均分。

```powershell
.\run.ps1 Run -Suite -Seed 12345 -Headless
.\run.ps1 Run -Map Map01 -File fixtures/bombs/Map01_regression_sentinel.json -Seed 12345 -Headless
.\run.ps1 Run -Map Map01 -File fixtures/bombs/Map01_regression_sentinel.json -Seed 42 -Headless
.\run.ps1 Run -Map Map01 -Layout stress_far_wall_five_pairs -Seed 12345 -Headless
.\run.ps1 Run -Map Map01 -Layout stress_far_wall_five_pairs -Seed 42 -Headless
.\run.ps1 Test -Suite
```

用户上传回放的原始输入在 `evaluation/v13_2_stability_20261015/reported_final1/某局/bombs_input.json`，按该局 `metrics.json`的seed重跑，例如：

```powershell
.\run.ps1 Run -Map Map05 -File evaluation/v13_2_stability_20261015/reported_final1/Map05_reported_r1_seed20261013/bombs_input.json -Seed 20261013 -Headless
.\run.ps1 Replay -Map Map05 -Layout reported -Seed 20261013
```
