# 无人机让行、空载聚集与卡墙修复

正式蓝方 v13.3（2026-10-15）。对应冻结候选 candidate10；逐局结果见 [避让修复验证结果](08_避让修复验证结果.md)。

## 原问题是什么

用户给出的 Map1 原回放在 1806 步触发 90 秒墙钟限制，只归位 9/10。源码与此前成功压力测试相同，前 1805 帧无人机位置、朝向以及炸弹位置逐值一致；此前运行更快，1945 步才完成。拥堵此前就存在，不能用一次成功推断已经稳定。

另一份 Map3 回放虽然全归位，健康度只剩54.2%，229点总损血中约165点发生在空载阶段。多架空载机同时追逐同一区域的共享线索，或者在墙端、狭窄区域挤成一团，既损血又干扰运输。

原来有载弹优先的让行函数，但它主要针对正在移动的迎头相遇。默认轨迹控制的多条路径直接返回动作，没有统一进入那个函数；已停住、侧向占道、待命状态也难以触发。

此外，原轨迹预测对机间距使用固定23像素余量。当公开定位带噪声、几架机已挤进这个余量时，六步预测内可能没有任何动作能立即达到23像素，连逐步扩大间距的动作也被拒绝。反复刹车不能解开这种队列。

## 实际动作在哪里接入

实现文件：

- `src/swarm_rescue/solutions/upgrade/controller_v13.py`：控制流程、公开消息、运动目标重定向。
- `src/swarm_rescue/solutions/upgrade/carrier_traffic.py`：载弹通行优先级与空载机脱困状态。
- `src/swarm_rescue/solutions/upgrade/trajectory_control.py`：只在空载脱困时允许逐步增加机间距。

正常规划产生运动目标后，先检查是否需要让行或脱困。需要时把目标换成短距离退让点，再交给原来的轨迹碰撞控制器。待命、近距离取弹等没有走轨迹规划的分支，也有统一的检查入口。不会仅写一个没有实际调用的优先级函数。

临时退让点和任务目标分别处理：到达退让点只能表示让行动作完成，不能向上层返回“已到达炸弹目标”。传感器无效时继续保留原有回退处理，避免修复运动逻辑时改变任务状态机的含义。

载弹机继续使用原来的载荷、机身双圆碰撞检查和处置流程，不为让路释放炸弹。

## 载弹机被空载机堵住时

`CarrierRightOfWay`仅使用有效的无线电位置、携带状态、里程计速度，以及队友公开的原运动目标。

1. 观察载弹机连续约24步的运动。净位移小于30像素、活动范围有限，并且通道附近存在多架空载机时，才视为持续队列。
2. 空载机位于载弹机前方约65像素的通道内，或已经靠得很近时，寻找侧移点。单机正常交会继续使用原运动逻辑，避免过早打断取弹。
3. 在多个方向、多个距离上生成候选点。LiDAR可见直线路径、在线墙图、已观测处置区、附近队友占用都参与检查。候选点还偏向原任务的前进方向，避免退到墙的错误一侧。
4. 选定后短暂保持，直到载弹机通过、消息失效或超时；释放后重新规划原任务路线，避免每一帧左右改主意。

距离都使用模拟器像素单位，没有读取某张地图的墙端坐标，也没有按seed选择动作。

## 空载机互相挤住、贴墙时

`EmptyCongestionRecovery`检查约64步的自身运动窗口。当净位移很小，同时靠近在线墙体或新鲜队友位置时，尝试局部脱困。触发依据是几何和运动，不是实际扣血冷却；健康仅作为诊断数据。

空载机之间使用稳定编号确定退让顺序。较低优先级机尝试退出队列，独自贴墙时也允许恢复。退让点必须具有可用路径，并与队友留出间隔；找不到可用点时不会直接朝未知墙体强行运动。退让持续时间有限，结束后重新规划。

脱困只临时重定向运动目标，不直接撤销任务认领，不新增附近炸弹的冷却，不删除或合并炸弹记录。途中若重新看到可以接近的未抓取炸弹，且没有紧贴队友，就退出通用脱困并恢复原取弹逻辑。任务归属、身份判定和负观测继续由原有模块处理；真实炸弹始终需要实际归位。

短时限任务保护原开局侦察与取弹节奏：通用空载脱困只在已确认处置奖励加新鲜物理载弹机数量达到预期炸弹数后启用。掉弹或载弹消息失效会使条件失效，恢复正常搜索。长时限任务全程启用载弹队列让行；短时限任务将新队列仲裁限定在远离已观测处置区的长程运输路段，近端快速取弹与交会保留原流程，减少对开局搜索的干扰。远近依据公开场地尺寸与在线观测位置计算，不按地图名或seed判断。这个条件只控制一种可选恢复动作，不用来结束比赛或伪造归位数。

全部剩余载荷都有真实携带者时，满足额外安全条件的空载机可以就地刹车待命：不能看到未抓取炸弹，LiDAR最近有效距离至少60像素，120像素内没有新鲜载弹队友，而且当前没有正在执行的让行或脱困。靠近墙体、附近载弹机需要通行、掉弹、新炸弹出现或消息失效时，都不能维持这个待命。任务记录保留，仍等待引擎实际处置完全部炸弹。

## 为什么还需要修改碰撞预测

原碰撞约束可能拒绝所有短距离逃离动作。例如两侧队友经公开定位估计距本机均约19像素，六步内即使向侧方移动、同时拉开距离，仍可能达不到23像素余量，动作就被全部判为不可用。

新模式仅在已经确认的空载退让/脱困动作中启用：对于起点已经不足23像素的队友，允许逐步扩大间距，而不是要求一步达到完整余量。起点已经满足余量的队友仍使用原阈值；LiDAR障碍预测仍在。载弹机检查不放宽，普通行驶也不启用。每次调用后恢复原控制器标志。

这是局部拥堵恢复启发式，包含噪声与有限预测，不是形式化无碰撞保证，也不保证所有机每一帧都持续移动。

## 怎么检查效果

先检查实际归位数，再看完成时间、健康与轨迹。近距离或低速帧可能包含正常等待，不能全部当作碰撞；持续低位移同时损血的区间更值得检查。

## 验收范围

需要完成五图三布局、Map1多seed与紧邻压力布局、此前用户回放、新用户Map3重复，以及带窗口的Map1复现。所有测试局必须真实归位10/10，五图各三布局等权平均分不得低于此前正式v13.2的95.277333；个别布局允许小幅波动。

电脑负载、显示开销仍可能影响墙钟上限和扣血冷却。有限测试通过不能外推到任意新地图、特殊区域、seed或极慢硬件。详细逐局证据和未解决边界以最终验收报告为准。
