# 03 · 查看回放与计算得分

## 1. 已带哪些回放

- `replays/v13_3/`：当前正式版，包含新用户场景、重复与多seed验证。
- `replays/v13_2/`：历史版的五图三布局、多seed及压力/用户回放场景，使用 `Replay -List`查看。
- `replays/v13_1/`：历史2026-10-12版本8局。
- `replays/v4/`：2026-10-04旧v4的15局，不是v13.1成绩。
- `replays/index.json`：每局的版本、地图、布局、种子、分数、归位数、相对文件路径及校验哈希。
- `docs/history/v4/旧v4_15布局与分数.pdf`：对应旧15局的布局PDF，明确属于历史v4。

```powershell
.\run.ps1 Replay -List
.\run.ps1 Replay -Map Map01 -Layout historic
.\run.ps1 Replay -Map Map01 -Layout stress_far_wall_five_pairs
.\run.ps1 Replay -Version v4 -Map Map05 -Layout edge_pairs
```

默认选择 v13.3；用 `-Seed 42`选择其他已保存seed。未打包组合须先运行生成回放，或用 `-File`指定文件。

## 2. 新运行的回放

找到`results/本次目录/某局/recordings/*.npz`：

```powershell
.\run.ps1 Replay -File 'results/本次目录/某局/recordings/team006_Map01_none_rd1.npz'
```

原始启动方式为`python -m swarm_rescue.launcher --replay <NPZ路径>`。回放需现有地图类已注册。不要加`--headless`，它不支持回放窗口。NPZ是逐帧状态文件，不能直接用视频播放器当MP4打开，也不会重新运行算法。

快捷键：空格播放/暂停，左右前后跳30帧，上下调1-10倍速度，Home回开头，End到末帧，Q/Esc退出。回放主要用于轨迹、绕行、卡住和归位诊断；分数与健康统计以CSV为准。

## 3. 蓝方单局分数

当前competition权重：

```text
总分 = 0.6 × 处置百分比 + 0.2 × 健康分 + 0.2 × 时间分
探索权重 = 0
```

三项原始分均为0-100。找到、认领、抓住都不算完成处置，炸弹进入处置区并被实际处置才计数。

- **处置D** = 实际处置数 / 初始炸弹数 × 100。10枚时每归位一枚贡献总分6分。
- **健康H** = 剩余无人机健康总和 /（初始机数 × 每机初始健康50）×100。现有地图没有额外返航区域，所以主要统计全场剩余健康，不是要求十机都回到出生点；自定义ReturnArea会改变统计范围。
- **时间T**：没有损毁时，`clamp((L - t)/(L - 0.5L), 0, 1) × 100`。L是本图步数上限，t是终止步数；到L的一半及以前满时间分，到L时0。被标记Crashed的局时间分为0。

Map01的L=2000，因此1000步以内才拿满时间分；Map02-04满时间分阈值2500步，Map05阈值3600步。墙钟限制也会终止运行，不能只看步数预算。

**墙钟先超时且步数未用完时，未全部归位仍可能有时间分。** 因而高总分不能替代全部归位的硬要求。碰撞扣血使用真实时间冷却，机器速度、后台负载和射线后端会影响健康及完成表现。

实际例子：v13.1的Map01历史布局，10/10归位、健康91.8%、1564步：

```text
D = 100；H = 91.8；T = (2000 - 1564)/1000 × 100 = 43.6
总分 = 60 + 18.36 + 8.72 = 87.08
```

压力布局9/10、健康78.2%、2000步：`54 + 15.64 + 0 = 69.64`，仍不满足全部归位。

## 4. 用文件自动复算

```powershell
# 默认查看当前正式版五图三布局15局成绩
.\run.ps1 Scores

# 查看刚跑的一批，替换为真实目录名
.\run.ps1 Scores -File results/本次目录

# 单个CSV也可以
.\run.ps1 Scores -File results/本次目录/某局/team006_stats.csv
```

会逐行显示处置、健康、时间、总分，复核60/20/20公式，并统计全部归位局数与Config Weight加权平均。不要把不同版本的目录混起来算同一版本均分。CSV有舍入差，复算容许约0.02分。

CSV关键字段：`Rescued Percent`实际归位百分比，`Health Return Score`健康，`Time Score`时间，`Round Score`单局总分，`Elapsed Time Step`终止步数，`Rescue All Time Step`全归位完成步数（失败局不能把0解释为更快），`Real Time Elapsed`墙钟秒数，`Crashed`损毁/异常标志。

原本配置可能关闭统计，此项目准备的配置和统一运行工具均开启`stat_saving_enabled`与`state_recording_enabled`。只看回放文件无法完整代替正式CSV评分。

## 5. 评分源码与红方

蓝方公式：`src/swarm_rescue/simulation/reporting/score_manager.py`；健康：`simulation/gui_map/map_abstract.py`；跨配置汇总：`simulation/reporting/stats_computation.py`。本地模拟器按每行Round Score与Config Weight加权平均。

红方为地图精度50%、布局难度20%、墙体覆盖20%、时间10%。布局难度须参考蓝方运行，单独红方局不能完整算出该20分。详见[赛题评分说明](reference/赛题与评分详细解读.md)和`place_score_manager.py`。本项目当前主要维护蓝方赛道。
